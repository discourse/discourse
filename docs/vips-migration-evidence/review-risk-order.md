Review the smallest contracts first, then the operations that can replace uploaded pixels or affect the widest set of thumbnails. The ordering below is a review-risk judgment, not a claim that earlier operations cannot fail or that recorded tests establish universal compatibility. It uses the existing [remaining-callsite audit](remaining-callsite-audit.md), [exact branch manifest](review-stack-manifest.json), final operation evidence and the narrow caller paths already identified in this task.

Practical merge order remains the prepared linear stack: **01 animation → 02 SVG dimensions → 03 SVG assets → 04 OG → 05 HEIF → 06 ICO → 07 JPEG → 08 orientation → 09 downsize → 10 resize → 11 crop**. Each branch is based on its predecessor. SVG assets/OG reuse SVG infrastructure; JPEG introduces shared source-quality/sampling support used later; geometry operations share loading/saving helpers. Reviewing orientation before JPEG, or crop/resize before downsize, means examining those branch deltas with their dependencies present, not merging them first. Reordering merges would require an intentional restack and renewed source alignment/verification.

This is why ICO’s narrow favicon path still ranks above HEIF’s native decoder, OG ranks above its stack neighbors, and downsize ranks above the wider thumbnail resize path: implementation surface and irreversible pixel replacement matter alongside caller count. Thumbnail crop/resize failures usually affect derived outputs; upload downsize, orientation and conversion can determine the retained original representation. Temporary-file adoption reduces partial-write risk but does not prevent a successful-looking visual regression.

All prepared operations use the existing default-off feature flag; disabling it retains the legacy processing path. There is no claim of transparent ImageMagick fallback for native failures. Existing optimizers remain a separate stage: raw ICC retention does not prove post-optimizer color or metadata parity, and the optimizer evidence owner’s final findings should be applied before publication. Shared JPEG sampling and SVG background evidence cover known cross-operation changes, including deliberate uncommon 422/440→444 encoding and filtered-edge differences.

The integration audit found no missed enabled-path production image-processing operation beyond the remaining quality probes. The ImageMagick problem check still tests executable availability and is not a transform; reconsider it when the last quality dependency is removed. Letter-avatar/dominant-color work predates these eleven prepared deltas and is outside this ordering. Exact review-head tests, publication state and CI are separate from risk ranking; this document does not report or infer their status.
