## Format contract

The vips-enabled path preserves Discourse behavior for JPEG, PNG, GIF and animated GIF, WebP and animated WebP, HEIC/HEIF, AVIF, sanitized SVG, ICO, TIFF, and JPEG XL wherever the existing caller accepts that format. This does not broaden `OptimizedImage` eligibility: TIFF remains outside `FileHelper.supported_images`, JPEG XL uploads remain accepted without generated optimized images, HEIC/HEIF uploads are converted to JPEG before downstream transforms, and SVG optimized images remain byte-for-byte copies. Docker loader checks prove that the stock build does not delegate to ImageMagick or Ghostscript. Libvips classifies JPEG XL and SVG loaders as untrusted; only the operations that require those formats opt into them, while `Discourse::SafeExec`, filesystem allowlists, network denial, timeouts, and resource limits remain active.

## Visual parity contract

The high-detail resize, north crop, and shrink-only comparisons decode both processor outputs to RGBA and require normalized mean absolute channel error at or below `0.03` on a `0..1` scale. This threshold permits expected encoder, resampler, and antialiasing differences while rejecting visible geometry, orientation, transparency, or color failures. Both outputs must also have identical dimensions and the vips encoded size must remain between `0.5×` and `2×` the ImageMagick output. The all-orientation JPEG comparison allows `0.10` because it compares two independently re-encoded JPEGs; it separately requires identical upright dimensions, orientation reset, and retained source quality.

## Cache contract

Letter avatars use the unconditional vips implementation fingerprint from discourse/discourse#42150. Optimized images use distinct processor versions for ImageMagick and vips, so changing `use_vips_for_image_processing` cannot reuse an artifact generated by the other processor.
