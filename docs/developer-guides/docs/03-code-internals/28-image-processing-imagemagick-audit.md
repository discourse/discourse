# Image Processing ImageMagick Audit

This manifest records the ImageMagick-dependent behavior that must stay stable before any CLI-vips port. It is intentionally about public behavior and observable outcomes, not current command strings.

## Infrastructure And Deployment

| Surface | Role | Current coverage | Port risk |
| --- | --- | --- | --- |
| `lib/image_magick.rb` | Shared wrapper for all direct `magick` and `identify` calls, with Landlock, environment allowlist, temp scratch, timeouts, rlimits, no network | Covered indirectly by runtime specs and sandbox specs | The vips CLI wrapper must preserve read/write allowlists, temp behavior, timeouts, failure exceptions, and no-network execution |
| `config/initializers/003-imagemagick.rb` | Forces `MAGICK_CONFIGURE_PATH` to Discourse policy and rejects external overrides | Policy specs cover effective allowlist | vips port should remove or replace only after all callers stop requiring ImageMagick |
| `config/imagemagick/policy.xml` | Allows only required coders and resources, including `MSVG`/`MVG` for internal SVG rasterization; denies delegates, filters, unsafe paths, stdio/fd, `/etc`, traversal, and symlinks | `spec/initializers/imagemagick_policy_spec.rb` | Replacement needs equivalent format/delegate/path/resource fail-closed tests |
| CI and containers | Development docs and base images install ImageMagick plus optimizer binaries | Mostly docs/container dependency references | Deployment dependency removal is separate from behavior port and must not happen during characterization |
| Test-only commands | Some specs and fabricators still call `identify`/`magick` directly for fixture setup or quality probes | Existing specs pass but some assertions are implementation-heavy | Prefer `FastImage`, `ChunkyPNG`, stored state, or parsed outcomes when replacing |
| Historical docs/locales | Setup docs and problem-check translations mention ImageMagick | Locale/problem-check specs | Text can only change after the port is complete and runtime dependency is removed |

## Coverage Status

High-risk behavior with characterization now present: core resize/crop/downsize dimensions, wrong-extension upload detection, PNG/JPEG policy exemptions, HEIC conversion, ICO-to-PNG conversion, animated GIF/WebP preservation, transparent PNG alpha retention, SVG cleaning and dimension probing including external references and entities, deterministic topic-OG rasterization, dominant-color success/failure caching including 16-bit input, letter-avatar dimensions including a non-ASCII username, image_optim sandbox routing, policy allowlist loading, and problem-check states.

Remaining high-risk gaps before a CLI-vips port: EXIF asymmetric corner markers, hostile SVG mask/viewBox/malformed XML cases, topic-OG SVG asset/failure cases, semantic crop-position/alpha-halo/profile checks, conversion-failure temp/store cleanup, S3 thumbnails with real processing, AVIF animation where supported, and optimizer worker cleanup behavior.
